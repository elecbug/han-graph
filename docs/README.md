# HAN-GRAPH 개발 기준

## 어떤 프로젝트인가

비한자권 한국어 학습자가 **처음 보는 한자어의 뜻을 구성 요소와 문맥으로 추론**하도록 돕는 학습 도구다. 주요 사용자는 이미 한국어 어휘를 어느 정도 아는 중급 이상 학습자이며, 초기 학습 언어는 한국어와 영어다.

단어를 입력하면 한자 구성과 뜻을 확인하고, 같은 한자를 공유하는 다른 단어로 이동한다. 이후 문맥 속 동음이의어를 구별하고, 배운 한자가 들어 있는 새로운 단어의 뜻을 추론하는 연습으로 이어진다. 최종 성과는 암기한 한자 수보다 **학습하지 않은 단어를 해석하는 능력**으로 평가한다.

기존 [README](../README.md)의 학습 목적과 단어 중심 데이터 구축 원칙을 기준으로 삼는다.

## 현재 상태

| 항목 | 상태 |
| --- | --- |
| 음 그룹 | `meta.jsonl` 411개 |
| 한자 | 글자 1,852개, `character.jsonl` 독음 레코드 1,858개: ID 번호 기준 중등 900, 고등 900, 확장 58 |
| 단어 | `normal_word.jsonl` 793개, 첫 170개 한자에 연결 단어 최소 5개씩 |
| 그래프 | 단어와 한자의 연결 1,715개, 단어가 연결된 한자 690개 |
| 실행 기반 | Go 1.26.2 이상, 외부 라이브러리 없는 CLI와 로컬 웹 앱 |
| 구현 기능 | 데이터 검증, 단어·한자 검색, 구성 분해, 연결 그래프, 브라우저 단어장, 한국어·영어 UI, 문맥 연습 6문항 |
| 아직 없는 기능 | 검수된 확장 학습 세트, 미지 단어 평가, 누적 학습·복습 기록, 계정 동기화, 사용 빈도·중심성 분석 |

실시간 수치는 `cd src` 후 `go run ./cmd validate`로 확인한다. 위 수치는 구조를 점검한 결과이며, 모든 훈음·번역을 사전과 대조했다는 뜻은 아니다.

시작 시점에는 코드가 이전 폴더명 `data/`를 참조했고, 단어 파일에 JSON이 아닌 진행 메모가 들어 있었다. 데이터 경로를 고치고 메모를 [데이터 작업 기록](../dataset/README.md)으로 옮겼다. 이후 어휘를 확장하면서 `灰`의 ID를 `hui-200`에서 `hoe-200`으로 교정하고, `彫`를 추가했다. 표기·풀이 수정과 출처 대조 범위는 데이터 작업 기록에 남긴다.

## 구현 방향

1. JSONL을 편집 가능한 원본으로 유지한다. 프로그램이 읽을 때 구조와 참조를 검증한다.
2. 단어에서 연결을 생성한다. 한자마다 단어 목록을 중복 저장하지 않는다.
3. 한글 표기가 같은 단어를 덮어쓰지 않는다. `분수/分數`와 `분수/噴水`는 서로 다른 항목이다.
4. 한자는 글자와 독음 레코드를 구분한다. 여러 독음이나 두음법칙을 단순 문자열 분해로 확정하지 않는다.
5. 데이터의 오류를 먼저 드러낸다. 구조 검증과 언어 내용 검수는 별도 작업이다.

자료의 정확한 형식, 연결 규칙과 현재 제한은 [데이터 모델](DATA_MODEL.md)을 참조한다.

```text
dataset/*.jsonl
    → 구조·중복·참조 검증
    → 단어 ↔ 한자 역색인
    → CLI / JSON API
    → 웹 탐색·단어장·기초 문맥 연습
```

현재 규모에서는 메모리 안의 인접 목록으로 출발한다. 그래프 데이터베이스나 병렬 처리의 도입은 실제 데이터 규모와 측정 결과에 따라 결정한다.

## 다음 개발 순서

### 1. 데이터·조회 기반 — 완료

- 실제 파일을 읽는 실행 명령과 오류 위치 표시
- 단어 구성 순서와 참조 무결성 확인
- 단어 분해 및 한자별 연결 단어 조회
- 동음이의어, 반복 한자, 복수 독음, 잘못된 데이터 회귀 테스트

### 2. 첫 학습 세트 — 793개 어휘 확장, 예문 검수 진행 예정

첫 170개 한자에 단어를 최소 5개씩 연결한 793개 세트를 만들었다. 感[감]의 연결 단어는 8개다. 감각·검객·경계(境界)·고고학·공공·관광처럼 여러 대상 한자가 공유하는 단어는 한 번만 수록한다. 다음 순차 수집은 `gwang-001`(廣[광])부터이며, 앞으로 한 번에 20개 한자씩 진행한다. `降[강/항]`, `切[절/체]`, `更[갱/경]`, `車[거/차]`, `率[률/솔]`, `不[불/부]`는 독음별 레코드로 저장하며 같은 글자의 연결 단어를 공유한다. 갱신·경신처럼 한자가 같고 한글 표기가 다른 단어도 별도 항목이다. 경신(庚申)은 전통 달력의 용어로 경신(更新)과 구별한다. 구경(九卿·口徑·究竟), 경계(境界·警戒), 계간(季刊·溪澗), 계승(繼承·階乘), 사고(事故·思考), 가공(架空·加工), 과실(果實·過失), 과장(課長·誇張), 관리(官吏·管理), 관용(寬容·慣用) 등도 한자와 뜻에 따라 구분한다. 공헌은 현대 학습 표기인 貢獻으로 정리했다. 이후 `文`, `學`, `水`, `電`, `分`처럼 이동과 추론을 보여줄 묶음도 확장하며 다음 내용을 검수한다.

- 한자 표기, 한국어 풀이, 영어 뜻과 품사 구분
- 구성 의미를 보여주는 힌트와 실제 사용 예문
- 자료 출처와 검수 상태를 기록할 필드 설계
- `분수/分數`와 `분수/噴水` 같은 문맥 대조 사례
- 기존 데이터의 훈음·로마자 표기와 TARGETS 표 오류 점검

완료 기준: 각 단어의 구성과 뜻을 확인할 수 있고, 연결 단어 탐색 및 문맥 대조에 쓸 수 있는 검수된 사례가 준비되어 있다. `噴`은 현재 한자 파일에 없으므로 해당 학습 세트에 필요한 확장 한자도 함께 등록해야 한다.

### 3. 탐색 화면 — 초기 버전 완료

Go 서버와 HTML·CSS·JavaScript로 단어 검색 → 구성 한자 확인 → 연결 단어 이동을 구현했다. 한국어·영어 전환, 모바일 배치, 키보드 조작과 브라우저 단어장을 제공한다. 상세 구조와 실행 방법은 [학습 웹 앱 문서](WEB_APP.md)를 참조한다.

### 4. 문맥 추론 연습 — 기초 흐름 완료

기존 단어를 활용한 6개 예문 초안, 단어 선택, 한국어·영어 해설, 결과와 오답 목록을 구현했다. 다음에는 예문 검수를 거쳐 같은 표기의 한자 구성 대조와 미지 단어 평가로 확장한다. 학습용 단어와 평가용 단어를 분리하는 작업은 아직 남아 있다.

사용 빈도, 의미 군집, 개인화와 연구용 네트워크 지표는 그 이후 확장한다. 단어 연결 개수는 현재 데이터의 수집량에 영향을 받으므로 실제 언어 사용 빈도로 취급하지 않는다.

## 개발과 검증

저장소 루트에서:

```sh
cd src
go run ./cmd serve
# 웹 서버 중지 후 CLI 실행
go run ./cmd validate
go run ./cmd word 가격
go run ./cmd character 家
go run ./cmd character 가
go run ./cmd -json word 번화가
go test -count=1 ./...
go vet ./...
```

기본 데이터 경로는 **실행 위치 기준 `../dataset`**이다. 다른 위치에서 실행하는 바이너리에는 `-data`로 경로를 지정한다. 옵션은 `word`, `character`, `validate` 앞에 둔다. 조회는 정확히 일치하는 표기를 사용하며, 검색 결과가 없으면 성공 상태와 빈 목록을 반환한다. 잘못된 명령은 종료 코드 2, 데이터 오류는 1이다.
