# 데이터 작성·검수 원칙

[프로젝트 현황](README.md) · [데이터 모델](DATA_MODEL.md) · [개발 안내](DEVELOPMENT.md) · [데이터 작업 기록](../log/UPDATE_LOG.md)

어휘 수집과 문맥 연습에 계속 적용할 기준을 정리한다. 파일 형식과 프로그램의 검증 규칙은 [데이터 모델](DATA_MODEL.md)을 따른다. 날짜별 작업 내역과 출처는 [작업 기록](../log/UPDATE_LOG.md)에 남기며, 과거 기록에 담긴 계획이 이후 변경된 경우에는 이 문서의 현재 기준을 적용한다.

## 학습과 편집의 기준

- 학습 목표는 단어의 구성 요소와 문맥을 바탕으로 뜻을 추론하는 능력이다. 한자 자체의 암기나 한자 표기 구별을 퀴즈의 목표로 삼지 않는다.
- 실제 쓰이는 어휘·전문 용어·고정 성구를 수록한다. 연결 개수를 채우기 위해 임의로 단어를 만들거나 긴 구절을 잘라 표제어로 삼지 않는다. 표제어 여부가 불분명하면 사전·문헌의 표기와 용례를 확인한다.
- 뜻풀이·번역·의미 힌트와 연습 예문은 학습용으로 직접 작성한다. 외부 자료는 표기·뜻·사용 맥락을 대조하는 데 쓰며, 사전 예문을 복제하지 않는다.
- 기존 단어·ID·독음·레코드 순서를 보존하면서 추가한다. 잘못된 내용을 교정할 때는 변경 이유와 출처를 기록하고 관련 참조를 함께 확인한다.

## 순차 수집과 보강 범위

순차 수집은 **한 번에 다음 20개 한자, 한자당 연결 단어 최소 5개**를 기준으로 한다. 이전 10개씩 진행하던 범위의 두 배이며, 매 차수마다 다시 두 배로 늘리는 뜻은 아니다. 기존 단어와 대상 한자 사이에 공유되는 단어를 재사용하므로 새 단어 수는 100개보다 적을 수 있다. 여러 독음은 글자 하나의 연결을 공유하며, 같은 `(word, hanja)` 쌍은 중복 저장하지 않는다.

순서는 `character.jsonl`의 초기 대상 목록을 따른다. 단어 구성에 필요한 추가 한자·독음을 파일 끝에 등록하는 일은 순차 수집 위치를 바꾸지 않는다. 대상과 추가 독음은 [수집 대상 기록](../dataset/TARGETS.md), 차수별 완료 위치는 [작업 기록](../log/UPDATE_LOG.md)에 남긴다.

**추가 목록 보강은 작업을 시작할 때 대상 집합을 고정한다.** 보강 중 새로 등록되는 한자·독음은 같은 작업이나 뒤이은 자동 재보강 대상에 편입하지 않는다. 나중에 별도 범위를 명시한 경우에만 새 대상으로 삼는다. 표기 교정에 필요한 글자를 추가하는 경우에도 같은 원칙을 적용한다.

초기 대상과 기존 고정 추가 목록의 보강은 완료된 상태다. 새 수집을 시작할 때는 완료 범위를 다시 확장하지 말고 작업 대상을 먼저 정한다. 현재 완료 범위와 데이터 규모는 [프로젝트 현황](README.md#현재-상태)에서 관리한다.

## 표기와 의미 설명

- 단어는 `(word, hanja)` 쌍으로 구분한다. 동음이의어를 사전의 별도 항목으로 보존하며, 반복 한자는 구성 순서에 모두 남기고 역방향 연결에서는 한 번만 센다.
- 같은 글자의 여러 독음을 보존하고 실제 어휘에 필요한 독음을 등록한다. 두음법칙이나 문맥 독음을 프로그램이 자동으로 추정한다고 가정하지 않는다. 이체자·문헌 표기를 임의로 치환하거나 합치지 않는다.
- 한국어·영어 설명에서 직접 쓴 한자는 매번 `字[음]`처럼 해당 문맥의 독음을 붙인다. 조회용 한자 원문과 구성 배열에는 독음을 붙이지 않는다.
- 한국어 의미 힌트는 친근한 해요체로 쓰고 문장을 `-요.`로 끝낸다. `이에요/예요`는 받침에 맞게 사용한다. 자세한 형식은 [뜻풀이와 힌트 작성](DATA_MODEL.md#뜻풀이와-힌트-작성)을 따른다.
- 실제 뜻과 구성 한자를 활용한 학습 설명을 구별한다. 대표 훈음 하나로 모든 용례를 설명하거나 근거 없는 어원을 만들어 내지 않는다. 여러 뜻·문어 용법·전문 분야·역사적 맥락을 필요한 만큼 밝혀 뜻을 좁힌다.

어휘 분류는 [일반·고전 분류 기준](DATA_MODEL.md#단어-normal_wordjsonl)에 따라 `(word, hanja)`별 사용 맥락을 검토해 정한다. 설명에 특정 키워드가 있다는 이유만으로 자동 분류하지 않는다. 문어적·격식적 표현을 일상 회화의 고빈도 어휘로 취급하지 않으며, 연결 수나 `normal`·`classical` 분류를 사용 빈도·난이도·TOPIK 등급으로 해석하지 않는다.

## 문맥 연습 작성

- **동음이의어 구별 문제는 출제하지 않는다.** 선택지는 서로 다른 한글 단어로 구성하고, 공백을 제외한 표기가 중복되지 않게 한다. 한자 표기 자체를 묻지 않으며 문장의 상황과 의미 단서로 답을 고를 수 있어야 한다. 한자 구성은 답을 고른 뒤 해설에서 참고한다.
- 문항을 추가할 때는 기존 정답의 `(word, hanja)` 쌍을 제외한 어휘에서 100개를 중복 없이 무작위 추출한다. 후보 순서·추출 방법·시드·묶음 ID를 작업 기록에 남겨 재현할 수 있게 한다. 기존 문항의 ID와 순서는 유지한다.
- 각 문항에 직접 작성한 한국어 문맥, 영어 번역, 기존 어휘를 참조하는 선택지와 한영 해설을 제공한다. 정답이 하나로 정해지는지, 오답과의 차이를 설명할 수 있는지 검수한다. 한국어 해설은 해요체와 독음 병기 규칙을 따른다.
- 새 문항에는 기본·응용·심화 난이도를 지정한다. 어휘뿐 아니라 문맥 단서와 선택지의 의미 차이를 함께 판단하며, 어휘 분류와 난이도를 동일시하지 않는다. 구체적인 기준과 회차 추출 규칙은 [문맥 연습 데이터 모델](DATA_MODEL.md#문맥-연습-practicejson)을 따른다.
- 예문·해설의 현재 검수 상태는 `draft`다. 구조 검증을 통과해도 예문의 자연스러움, 난이도, 해설의 정확성에 대한 내용 검수는 별도로 진행한다.

## 검증과 기록

데이터 변경은 전체 형식·중복·참조 검사와 변경 범위의 내용 검수를 함께 수행한다. 추가 작업에서는 기존 항목 보존, 고정 대상의 최소 연결 수, 새 독음과 설명의 독음 병기, 연습의 정답·선택지 참조를 확인한다. 명령과 웹 검사 범위는 [개발 안내의 검증 절차](DEVELOPMENT.md#검증)를 따른다.

외부 출처를 선별 대조한 결과와 전체 자동 검사 결과를 구분해 기록한다. 일부 항목을 대조했다고 전체 어휘가 외부 사전 대조나 전문가 감수를 마쳤다고 표현하지 않는다. 구조 검사 통과만으로 뜻·번역·어원·학습 효과가 확인되는 것은 아니다.

JSONL에는 주석이나 진행 메모를 넣지 않고 [작성 형식](DATA_MODEL.md#파일과-작성-형식)을 유지한다. 개별 어휘 수정, 대조 출처, 수집 위치, 추출 시드와 실제 검증 결과는 `log/UPDATE_LOG.md`에 남긴다. 계속 적용할 원칙이나 모델·기능 변경은 해당 `docs/` 문서에도 반영하고, 현재 데이터 수치는 [프로젝트 현황](README.md#현재-상태)에서 관리한다.

## 남은 내용 검토

2026-09-16 품질 감사와 연습 작성에서 남긴 검토 항목이다. 검토를 마치면 이 목록을 갱신하고 교정 내용·근거는 작업 기록에 남긴다.

- `모독죄(冒瀆罪)`는 적용 법역이 분명하지 않고 풀이가 순환적이어서 출처 확인 뒤 구체화하거나 제외해야 한다.
- `정치기치`, `완두재배`, `범람위험`, `수렵생활`, `효시론`, `한발대책`처럼 일반 명사 결합에 가까운 일부 표제어는 실제 표제어성·용례 출처를 계속 확인한다. `효시론`은 이후 연습 작성에서 학술적 용례를 확인했지만 일반 사전의 표제어 여부까지 확인한 것은 아니다.
- 생성 힌트 다수는 구성 한자의 음을 나열하고 한국어 풀이를 반복한다. 구조는 정상이나 학습 설명으로는 얕으므로 출처가 있는 글자별 의미 설명으로 차례로 교체한다.
- 전체 한자 목록의 훈음·뜻과 연습 예문의 자연스러움·난이도·해설을 계속 검수한다. 단어별 구성 의미, 출처·검수 상태, 사용 빈도를 기록할 필드는 후속 데이터 모델 작업에서 설계한다.
- 부수·총획·필순은 현재 스키마와 코드에 필드가 없어 기존 감사 범위에 포함되지 않았다. 제공하려면 데이터 모델을 먼저 확장해야 한다.
