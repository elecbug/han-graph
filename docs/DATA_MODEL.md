# 데이터 안내

[프로젝트 안내](README.md) · [콘텐츠 원칙](DATA_GUIDELINES.md) · [기초 어휘와 출처](BASIC_VOCABULARY.md)

漢-Graph의 자료는 **단어, 구성 한자, 독음과 뜻**을 연결합니다. 공개 파일을 읽거나 다른 도구에서 활용하려는 분을 위해 자료의 구성과 식별 방법을 설명합니다.

## 단어와 한자는 어떻게 연결되나요?

‘가격’은 한글 표기, 價格은 한자 표기이며 구성 한자는 價[가]와 格[격]입니다. 같은 글자를 사용하는 다른 단어가 그래프에서 연결됩니다. 한자는 여러 독음을 가질 수 있으므로 글자와 독음 정보를 나누어 제공합니다.

단어는 **한글 표기와 한자 표기의 조합**으로 구분합니다. ‘유명’처럼 소리는 같아도 有名과 幽冥은 서로 다른 항목입니다. 같은 조합의 여러 뜻·용법은 하나의 풀이에 담습니다.

한글과 한자가 섞인 ‘검은색’은 `검은色`으로 표시하고 色[색]만 연결합니다. 한글 부분을 별도 한자로 간주하지 않습니다. 표기와 접미부 정리 기준은 [기초 어휘와 출처](BASIC_VOCABULARY.md)를 참고하세요.

## 파일과 작성 형식

| 파일 | 담고 있는 내용 |
| --- | --- |
| [word.jsonl](../dataset/word.jsonl) | 어휘 분류, 한글·한자 표기, 한영 뜻과 구성 한자 |
| [character.jsonl](../dataset/character.jsonl) | 한자의 독음별 뜻과 식별자 |
| [meta.jsonl](../dataset/meta.jsonl) | 한글·로마자 독음 그룹 |
| [practice.json](../dataset/practice.json) | 문맥 연습과 선택지·정답·해설 |
| [sources](../dataset/sources/README.md) | 참고 목록과 사전의 수록·제외 대응 |

JSONL은 UTF-8 텍스트로, 한 줄에 하나의 JSON 객체를 저장합니다. 세 JSONL 파일은 모두 필요하며 각각 하나 이상의 항목을 포함합니다. 빈 줄은 읽을 수 있지만 작성할 때는 주석·진행 메모·여러 줄 객체를 넣지 않습니다. 설명의 문장과 배열은 실제 항목 안에 담습니다.

자료 규모는 [프로젝트 안내](README.md#현재-상태), 이용 조건은 [데이터 라이선스](../dataset/LICENSE)와 [외부 출처 안내](../dataset/sources/README.md)에서 확인할 수 있습니다.

## 단어: `word.jsonl`

```json
{"level":"normal","word":"가격","hanja":"價格","meaning_ko":"물건의 값","meaning_en":"price","components":["價","格"]}
```

| 필드 | 의미 |
| --- | --- |
| `level` | `normal`: 일반 어휘, `classical`: 고전·문어 어휘 |
| `word`, `hanja` | 한글 표기와 한자·혼합 표기 |
| `meaning_ko`, `meaning_en` | 한국어 뜻과 영어 뜻 |
| `components` | 표기에 나타난 한자만 원래 순서로 담은 배열 |
| `semantic_hint` | 구성과 의미를 설명하는 선택적 학습 힌트 |

일반 어휘는 현대 한국어의 쓰임을, 고전·문어는 옛 호칭·제도·한문 구절이나 문어 중심의 쓰임을 구분합니다. 일반 어휘에도 전문 용어가 포함되며, 이 분류를 난이도나 TOPIK 등급으로 해석하지 않습니다. 같은 소리여도 의미와 쓰임이 다르면 항목별로 분류합니다.

‘강’처럼 한 글자 한자어도 수록합니다. ‘검은색’의 `hanja`는 `검은色`, `components`는 `["色"]`입니다. 반복되는 한자는 배열에서 원래 순서를 유지합니다.

<details>
<summary>단어 파일의 형식 조건</summary>

`level`, `word`, 두 뜻풀이는 비어 있지 않은 문자열입니다. `components`는 생략하거나 `null`로 둘 수 없고, 각 글자는 한자 파일에 등록되어 있어야 합니다. 같은 `(word, hanja)` 조합의 중복은 허용하지 않습니다.

한자 표기가 있으면 실제 한자를 하나 이상 포함하며, `components`는 그 한자들을 원래 순서로 담습니다. 혼합 표기의 한글 부분은 공백을 제외한 단어의 같은 위치와 일치해야 합니다.

파일 형식은 한자 없는 항목의 `hanja: ""`, `components: []`도 지원하지만 현재 사전의 수록 대상에서는 제외합니다. 허용 형식과 실제 수록 정책은 구분합니다. `level`은 형식 검사에서 비어 있지 않은지를 확인하며 분류의 적절성은 내용 검토가 필요합니다.

</details>

### 뜻풀이와 힌트 작성

설명에서 쓴 한자는 `字[음]`처럼 독음을 병기합니다. 한국어 구성 힌트는 해요체로 작성하며, 실제 의미와 학습을 위한 구성 설명을 구별합니다. 조회용 한자 표기와 구성 배열에는 독음을 덧붙이지 않습니다. 상세한 편집 기준은 [콘텐츠 원칙](DATA_GUIDELINES.md)에 있습니다.

## 한자 독음: `character.jsonl`

한 글자에 여러 독음이 있으면 독음별 항목을 제공합니다. 각 항목의 `id`는 음 그룹과 연결되고, `meaning_ko`와 `meaning_en`에는 한 개 이상의 뜻이 배열로 담깁니다.

<details>
<summary>한자 항목의 필드</summary>

| 필드 | 형식 |
| --- | --- |
| `type` | `character` |
| `id` | 음 그룹 ID와 하이픈, 세 자리 이상 숫자로 이루어진 고유 키 |
| `hanja` | 한 글자 |
| `meaning_ko`, `meaning_en` | 비어 있지 않은 뜻 문자열 배열 |

같은 글자·음 그룹 조합은 중복하지 않습니다. ID의 번호는 기존 자료에서 `000–099` 중학교용, `100–199` 고등학교용, `200` 이상 확장 독음에 사용합니다. 이 번호 자체가 단어의 난이도나 사용 빈도는 아닙니다.

</details>

## 음 그룹: `meta.jsonl`

같은 소리의 한자를 묶는 자료입니다. `id`는 그룹 식별자, `sound_ko`는 한글 독음, `sound_en`은 조회에 사용하는 로마자 표기입니다.

<details>
<summary>음 그룹의 필드</summary>

`type`은 `meta`입니다. `id`와 두 독음 필드는 비어 있지 않은 문자열이며 그룹 ID는 고유합니다. 로마자 표기는 자료에 저장된 값을 사용합니다. 별칭이나 특정 로마자 표기법에 따른 자동 변환은 제공하지 않습니다.

</details>

## 그래프와 조회

단어는 구성 한자와 연결됩니다. 같은 글자가 여러 번 나오는 단어도 한자별 연결 단어 목록에서는 한 번만 나타납니다. 한글 부분은 연결 대상에 포함하지 않습니다.

한자의 여러 독음은 후보로 함께 제공합니다. 문맥에 맞는 독음과 표기를 확인할 수 있도록 원본을 유지하며, 이체자·두음법칙에 따른 별칭을 자동으로 만들지는 않습니다.

### 화면의 깊이 1 그래프

화면에서는 선택 단어의 구성 한자 또는 선택한 한자에서 직접 연결되는 단어와 그 구성 한자를 보여 줍니다. 새로 나타난 글자를 따라 모든 연결을 계속 펼치지는 않습니다. 서로 다른 구성 한자가 여러 개면 하나의 단어 이름에 함께 연결하고, 한자가 하나면 그 주변에 단어 이름을 배치합니다.

화면 조작은 [사용 안내](WEB_APP.md#연결-그래프-읽기), 전체·소리 검색과 API 조회 조건은 [설치와 활용](DEVELOPMENT.md#http-api)에 설명합니다.

## 문맥 연습: `practice.json`

각 문항은 한국어 문맥과 영어 번역, 서로 다른 한글 단어로 된 선택지, 정답과 한영 해설을 포함합니다. 선택지는 기존 사전 항목을 참조합니다. 한자 표기는 항목을 식별하고 해설을 제공하는 데 사용하며 선택 버튼에는 한글 단어를 보여 줍니다.

난이도는 `easy`(기본), `medium`(응용), `hard`(심화)로 구분합니다. 일반·고전 어휘 분류와는 다른 기준이며, 일반 어휘에도 심화 문항이 있습니다. 현재 예문과 해설의 검수 상태는 초안입니다.

<details>
<summary>연습 파일의 필드</summary>

| 위치 | 필드와 형식 |
| --- | --- |
| 최상위 | `version: 1`, 출처 문자열 `source`, `review_status: "draft"`, 비어 있지 않은 `questions` 배열 |
| 문항 식별 | 고유 문자열 `id`, 난이도 `difficulty` |
| 문맥 | 비어 있지 않은 `prompt_ko`, `prompt_en` |
| 해설 | 비어 있지 않은 `explanation_ko`, `explanation_en` |
| 선택지 | 단어 참조 2–4개인 `options` 배열 |
| 정답 | 선택지에 포함된 단어 참조 `answer` |

단어 참조는 `{"word":"가명","hanja":"假名"}`처럼 한글·한자 쌍으로 지정합니다. 선택지에서 공백을 제외한 한글 표기가 중복되면 허용하지 않습니다. 현재 허용하는 검수 상태는 `draft`입니다.

API 응답의 `word_level`은 정답 단어의 분류에서 가져옵니다. 브라우저는 난이도와 정답 어휘 분류로 거른 뒤 최대 10문항을 고르고 선택지 순서를 섞습니다. 해당 조건에 문항이 없으면 시작할 수 없습니다.

</details>

## 검증 범위

파일 형식, 항목의 중복, 독음·구성 한자의 참조, 연습의 선택지·정답과 초급 목록 대응을 검사합니다. 자료를 읽는 중 오류가 있으면 파일과 위치를 알려 주며, 잘못된 항목을 조용히 건너뛰지는 않습니다.

형식 검사는 뜻풀이·번역·예문의 내용 감수나 학습 효과 검증을 대신하지 않습니다. 내용 검토 범위는 [콘텐츠 원칙](DATA_GUIDELINES.md#자료의-품질과-검토-범위), 확인 명령은 [설치와 활용](DEVELOPMENT.md#검증)을 참고하세요.
